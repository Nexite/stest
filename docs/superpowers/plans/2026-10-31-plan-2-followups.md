- PR #2 review fixes: Ruling: RCC emits `ModelContext::clock_tree_changed()` (Signal<ClockTree>) when a ClockTree output changes; TIM subscribes and re-anchors a running counter exactly at the change instant (resolves the Task 5 deferred "RCC clock changes not picked up live" + rescale truncation). ADC/SPI/DAC keep reading the clock tree at each operation start: an in-flight ADC calibration/ADRDY/conversion or SPI frame finishes at the old rate (microseconds; documented pattern in docs/adding-a-peripheral.md "Clock changes"). SysTick and DWT CYCCNT use the firmware's SystemCoreClock, not the RCC, and are unchanged — cost if wrong: an RCC change in the middle of a long ADC calibration / 640.5-cycle sample is timed at the old rate.
- PR #2 review fixes: Ruling: ITM honours the software lock (TER/TPR/TCR writes ignored while locked, one stderr warning per run); debugger-attached default stays unlocked (LSR = 1), as a debugger leaves it — cost if wrong: bare-board firmware that never unlocks gets no ITM output (matches hardware).
- PR #2 review fixes: Ruling: ADC CR ADEN / ADCAL written 1 while already 1 aborts only when no other rs bit is newly set in the same write; with one (CMSIS `ADC1->CR |= ADC_CR_ADSTART`) it is a read-modify-write carry and accepted. RM0351 forbids setting ADEN unless every other CR bit is 0, which the |= idiom technically violates, but it is ubiquitous and harmless on silicon; ST's LL masks the rs bits (ADC_CR_BITS_PROPERTY_RS) and HAL never rewrites them — cost if wrong: a carried ADEN=1 is not flagged.
